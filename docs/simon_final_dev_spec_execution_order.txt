SIMON 최종 개발 명세 + 실행 순서 (메모장용 텍스트)

[범위]

외부 판매 없음. 본인 PC / 본인 계좌 / 본인 운영 전용.
브로커: 한국투자증권(KIS) 단일. 키움 경로 폐기.
UI: 기존 사이먼 채팅창·대시보드 템플릿 재활용(경로·파일명은 로컬 실트리 기준). 이 저장소의 임베디드 페이지는 참고용일 수 있음.

[아키텍처 한 줄]

사이먼 = 오케스트레이터(분류, 울타리, 팩트 조립, 로그, 브로커 호출 정책).
Qwen2.5-14B = 감옥 내 자연어(말 생성). 주문 실행·토큰·비밀경로 유입 금지.
단일 진실(SSOT): 정규화된 브로커 스냅샷(숫자·체결·잔고). LLM은 스냅샷을 수정하지 않음.

[하드웨어 전제(대화 기준)]

RTX 3090 24GB: 14B Q5_K_M 또는 Q8_0 중 실측으로 하나 고정.
CPU i9-14900K 가정: Ollama 스레드는 실측 튜닝.
열/동시 GPU: 3090은 프로세스별 VRAM % 강제가 어려움 → 동시 추론 금지·YOLO 분리·해상도 축소 등으로 물리 분리.

[속도]

일반: Qwen 단일 호출 + SSE 스트리밍. temperature 0.1~0.2.
max_tokens는 낮게 시작하되 문장 중간 절단 방지: 종료 시퀀스 또는 JSON 모드 종료 규칙 병행.
num_ctx 8K~16K 고정(128K 금지).
시세·잔고 단순 조회: LLM 스킵 가능. 단, 입력이 회색지대면 보수적으로 LLM으로 이관.
시스템 즉답에는 화면에 [출처: 내부 규칙 엔진] 라벨.

[KIS 운영 리스크 대응]

모의 초당 2건: 토큰버킷/최소간격(500ms~1s) + 짧은 TTL 캐시(조회 UX) + 배치 조회.
주문 직전 판단: 캐시 강제 bypass 단, 429 방지 위해 단일 슬롯·우선순위 큐.
WS 실시간 등록 41건: 워치리스트 티어(A 보유·미체결·핀, B LRU, C 나머지). 초과분은 REST 폴링·온디맨드 구독 스왑. 미구독 종목은 UI에 실시간 아님 명시.
WS 고스트: 무수신 3~5초(튜닝) 시 세션 폐기. 재연결은 지수 백오프 + 단계적 재구독. 재접속 직후 REST 스냅샷 1회로 리콘실.
OAuth 토큰 발급 초당 1건: 단일 토큰 매니저, 만료 N분 전 선제 갱신, 루프 내 재발급 금지, 429 백오프.
토큰·키는 Qwen FACT_BOX 금지, 로그 원문 금지(해시·만료만). Regex 마스킹은 보조. Rolling 로그(용량 상한).

[주문 안전]

상태 머신: 기본 조회 전용. "주문 모드 시작" 명시 전까지 주문 함수 비활성(물리 분리 수준).
접수 200 OK != 체결. UI·TTS는 [접수 완료·체결 대기] 유지. 체결은 WS 체결 채널 매칭 후에만 완료 표현(필드명은 한투 문서 기준으로 매핑 테이블 고정).
멱등: 턴 기반 고유 주문키(한투 규격 필드) + 로컬 디바운스. 서버 중복 거부 여부는 문서·실측 확인.
긍정어 화이트리스트 매우 좁게. 부정어 혼입 시 무조건 거절. 가능하면 화면 최종 버튼을 음성과 동등 권한으로 병행.

[전산망 단절]

브로커 팩트 채널 down 시 LLM 라인 셧다운(또는 고정 경고 템플릿만). Qwen은 단절을 모름.

[장세 이상치]

동시호가·VI 등: null·이상값은 Data Corrupted로 잠금. 전일 대비 % 하드컷만 쓰지 말고 장세그먼트별 검증.

[음성]

TTS 중 STT bleed: AEC·TTS 게이트·PTT·하드 인터럽트 중 현실적으로 가능한 조합.
TTS는 speak_text, 숫자는 UI 단일 스키마.

[모의 vs 실전]

broker_profile kis_paper / kis_live URL·JSON 매핑 테이블 분리.
정규화 모델: NormalizedQuote, NormalizedBalance 등 내부 SSOT 단일.
실전 전환은 코드 직접 수정 금지, 프로파일 스위치 + 장전 계약 테스트 체크리스트(Human-in-the-loop).

[형상·SSOT]

로컬 main 실트리 단일 기준선. 임시 파일 난립 금지.
/api/status에 git_hash, broker_profile, token_expires_in 권장.

[오프라인 스트레스]

주말·야간에 429, WS 끊김, 키 누락, JSON 키 변형 샘플 주입. 계약 테스트에 샘플 고정.

[개인정보·로그]

qwen_raw 저장 시 사전 마스킹 + 순환 로그. 계좌·키 패턴.

================================================================================
실행 계획표 (순서대로)

단계 0 — 기준선 고정

로컬 main 실트리 확정. 채팅창·대시보드 HTML/JS 경로 목록 작성.
/api/status에 git_hash·broker_profile 노출(가능 시).
종료 정의: "이 커밋에서 UI가 뜬다" 스크린샷 1장 + status JSON 1개 저장.

단계 1 — KIS 어댑터 골격(읽기 전용)

인증: 토큰 매니저 단일 모듈. 재발급 폭주 방지.
REST: 잔고·현재가 1~2개만 먼저. 모의 프로파일만.
정규화 레이어 + 필수키 없으면 unknown/degraded.
종료: 모의에서 동일 질의 10회 반복 시 429 없이 동작(캐시·스로틀 포함).

단계 2 — 웹소켓(실시간) 최소

구독 상한 41 반영한 워치리스트 정책.
하트비트·고스트 세션 처리·재접속 후 REST 리콘실.
종료: 끊김 주입 테스트에서 SSOT 라벨이 거짓 실시간이 되지 않음.

단계 3 — 오케스트레이터 + Qwen 감옥

Ollama Qwen14B 클라이언트. FACT_BOX 화이트리스트. 토큰 유입 차단.
네트워크 단절 시 LLM 차단 분기.
turn_id, qwen_raw(마스킹), simon_final 저장 정책.
종료: "Qwen은 뭐라 했어?" 질문에 원문 인용 가능.

단계 4 — 채팅 UI 재활용 연동

기존 채팅창에 SSE 또는 동등 푸시로 user_message / bot_reply.
시스템 즉답 출처 라벨.
종료: 음성·텍스트 모두 로그에 동일 턴으로 남음.

단계 5 — 음성 파이프라인(재활용 + 보강)

Resident 또는 기존 STT 경로 유지. TTS는 speak_text 우선.
TTS 중 인터럽트 정책(AEC/PTT) 중 택1 실측.
종료: "아니 취소"가 주문 잠금 해제로 절대 오인되지 않음(보수 규칙).

단계 6 — 주문 경로(여전히 HOLD·승인 우선)

주문 모드 상태 머신. prepare만. 접수·체결 분리 UI.
멱등 키·디바운스.
종료: 모의에서 의도적 이중 발화에도 중복 접수 방지 확인.

단계 7 — 실전 프로파일 분리

kis_live 매핑 테이블·URL 스위치. 계약 테스트 샘플 분리.
Human 체크리스트 후에만 실전 키 장착.
종료: 모의·실전 각각 스모크 녹색.

단계 8 — 스트레스·회귀 고정

429, WS 갭, JSON 변형, 토큰 만료 시나리오 자동화.
requirements pinning 또는 lock 파일.
종료: 주말 배치 한 번에 전부 통과.
