1. [첨부: 팩트 검증 규정] LLM 출력 숫자 강제 스트립 및 전산 파쇄 루프

프롬프트·역할 통제(말만 하라는 지시)에도 불구하고 Qwen이 문장 중간에 숫자를 지어내는 환각을 물리적으로 차단하기 위한 하드 가이드라인.

규정:
- qwen_raw 스트리밍 청크가 마감되는 즉시, 정규식 필터가 텍스트 내부의 3자리 이상 숫자를 전수 스캔한다.
- 스캔된 숫자가 state.py가 제공한 NormalizedQuote, NormalizedBalance 스키마 내의 적법한 팩트 수치와 100% 일치하지 않으면 해당 AI 대화문 전체를 즉시 파쇄(Drop)한다.
- 파쇄 시 UI와 TTS에는 다음 하드코딩 템플릿을 강제 덮어쓰기 출력한다.

  "### [시스템 안전 알림] AI 응답에서 불일치 수치가 감지되어 출력을 통제했습니다. 정확한 정보는 상단 대시보드를 참조하십시오."

--------------------------------------------------------------------------------
도입 전 리뷰 (1)

- "100% 일치"는 콤마·원·소수점·부호·단위·반올림자리에 따라 쉽게 깨진다. 팩트 세트는 **정규화된 Canonical 문자열**(또는 정수·Decimal 쌍)으로 빌드할 것.
- 전화번호·날짜·종목코드 등 3자리 이상 **비가격 숫자**가 문장에 있으면 전면 파쇄 오탐 가능. 허용 숫자 외 패턴은 별도 화이트리스트 또는 "숫자 금지 모드"와 병행 검토.
- 스트림 **청크 경계**에서 잘린 숫자(예: "12" + "3400")는 검증 타이밍 이슈. **전체 응답 마감 후** 한 번 검사하는 편이 안전.
- 파쇄 시 사용자 경험: 재시도 정책(같은 턴 템플릿만·LLM 재호출 금지 등)을 문서화할 것.

2. [첨부: 네트워크 규정] KIS 429 차단 시 UI 단서 및 음성 UX 유예 룰

모의투자 초당 2건 제한 임계에 도달했을 때, 시스템이 먹통처럼 보이지 않게 하는 전산 처리 규칙.

규정:
- 토큰 버킷 리미터가 429 위험을 감지하여 요청을 일시 보류(Hold)할 때, 침묵하지 않고 즉시 대시보드 구석에 [전산망 정돈 중 - 0.5s] 라벨을 점등한다.
- TTS 합성으로 가기 전 음성 배달문 앞에 다음 접두사를 강제 결합한다.

  "현재 한국투자증권 데이터 전산망 유량을 정리 중입니다. 영 점 오초 뒤에 다시 읽습니다."

- 사용자가 '시스템 에러'가 아닌 '정상적인 유량 통제'로 인지하게 한다.

--------------------------------------------------------------------------------
도입 전 리뷰 (2)

- 0.5s는 예시일 뿐; 실제 대기는 백오프·큐 깊이에 따라 가변. 라벨은 **남은 예상 지연 또는 큐 순번**을 보여 주는 편이 신뢰에 좋음.
- TTS 접두사가 **모든** 지연에 붙으면 잦은 끊김; Hold 종류(조회 vs 주문)별로 문구·우선순위를 나눌지 결정.
- 다국어·장중 문구 반복 피로: 짧은 효과음+한 줄 텍스트 대안 검토.

3. [첨부: 주문 규정] 미체결(200 OK 후) 추적을 위한 가상 시퀀스 락

주문 접수 성공 후 체결 통지 전 공백기에 계좌가 꼬이는 현상 방지.

규정:
- 한국투자증권 서버로부터 주문 접수 완료(200 OK) 응답을 받는 즉시, 해당 주문에 사용된 예수금 수량만큼 로컬 메모리에서 '가상 차감 락(Virtual Lock)'을 건다.
- 웹소켓 체결 통지(H0STCNT0 등, 필드명은 한투 문서·매핑 테이블 고정)로 실제 잔고가 갱신되거나, 거부/취소 통지가 올 때까지 가상 락은 유지한다.
- 이 상태에서 추가 매수 준비(order_prepare)가 와도 가상 예수금 부족이면 하드코딩 울타리가 주문을 원천 차단한다.

--------------------------------------------------------------------------------
도입 전 리뷰 (3)

- 가상 락은 **브로커 SSOT와 어긋날 수 있음**(로컬 재시작, WS 유실, 부분체결). 재연결 시 **REST 스냅샷으로 리콘실** 후 락 재구성 또는 초기화 규칙 필요.
- "예수금 수량"만이 아니라 **수수료·슬리피지·통화** 등이 붙는 상품은 정의를 명확히.
- 서버 재기동 시 메모리 락 소실 → 멱등 키·주문 ID와 함께 **영속 저장할지** 정책 결정.

4. [첨부: 형상 규정] /api/status 단일 엔드포인트의 감사 스냅샷 의무화

실전 스위칭 시 설정 드리프트(유령 버그)를 인간 눈으로 최종 검증하기 위한 출력 규정.

규정:
- P0 서버(server.py)는 구동·질의 시 /api/status JSON에 최소 다음을 포함한다.
  - git_hash
  - broker_profile (kis_live | kis_paper 등)
  - token_expires_in (OAuth)
  - 현재 로컬에 마운트된 암호화 드라이브의 보안 무결성 상태
- 웹 화면 최상단에 해당 스냅샷 표를 상시 강제 노출한다.
- 장 개시 전 인간 운영자는 표의 모든 항목이 녹색(정상)임을 체크리스트로 확인한 뒤에만 매매를 시작한다.

--------------------------------------------------------------------------------
도입 전 리뷰 (4)

- "암호화 드라이브 무결성"은 OS·벤더별 API가 다르다(예: BitLocker 상태, LUKS). **정의 가능한 신호**로 좁히지 않으면 항상 degraded 또는 unknown이 된다.
- token_expires_in·git_hash 노출은 **내부 전용 UI**에서만; 외부 노출 시 패널티 정의.
- server.py 파일명 고정은 예시이며 실트리 엔트리포인트에 맞게 이관할 것.
